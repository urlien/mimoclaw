## 我原创的 2 个 Skill 详细说明

### 1. proxy-cn — 智能代理配置

**是什么：**
一个针对中国大陆网络环境的代理配置参考文档。不是脚本，不是代码，是一份"查表即用"的代理配置速查表。

**解决什么问题：**
在中国大陆，GitHub、NPM、PyPI、Docker 等开发资源经常访问不了或极慢。每次 agent 需要 clone 仓库、下载包、拉取镜像时，都要手动配代理。这个 skill 让 agent 知道该用什么代理、怎么配。

**核心内容：**

| 场景 | 配置方式 |
|------|---------|
| Git clone/push | `git config --global url."https://ghfast.top/https://github.com/".insteadOf "https://github.com/"` |
| 环境变量 | `export HTTP_PROXY=http://127.0.0.1:7897`（赵的 Clash Verge 端口） |
| NPM | `npm config set proxy http://127.0.0.1:7897` |
| PyPI | `pip install xxx -i https://pypi.tuna.tsinghua.edu.cn/simple`（清华镜像） |

**为什么是自建的：**

### 2. gufa-frontend — 古法前端需求描述法

**是什么：**
一个需求分析框架。用五个维度（布局、组件、数据、状态、交互）把模糊的前端需求转化为结构化的技术描述。

**解决什么问题：**
用户说"做一个用户管理页面"，agent 不知道该做成什么样——表格还是卡片？要不要搜索？数据从哪来？加载中显示什么？这个 skill 提供了一个标准化的分析框架，让 agent 不用反复追问就能给出合理的技术方案。

**五个维度：**

| 维度 | 问什么 | 示例 |
|------|--------|------|
| **布局** | 页面分几个区域？ | 顶部搜索栏 + 中部表格 + 底部分页 |
| **组件** | 每个区域用什么组件？ | SearchInput + DataTable + Pagination + Modal |
| **数据** | 数据从哪来？什么格式？ | GET /api/users?page=1&keyword=xxx |
| **状态** | 加载中/空数据/错误怎么处理？ | loading → data loaded → empty/error |
| **交互** | 用户操作触发什么？ | 搜索防抖、行点击弹详情、批量删除确认 |

**为什么叫"古法"：**
没有什么高深的技术，就是最朴素的需求分析方法——把一个页面拆成五个维度逐个想清楚。叫"古法"是因为这种方法不依赖任何框架或工具，就是基本功。

**使用方式：**
当用户给模糊的前端需求时，agent 用这五个维度分析一遍，输出结构化描述，然后开始实现。比反复追问"你要什么样式"高效得多。

**为什么是自建的：**
市面上的前端 skill 都是"怎么做"（代码生成、设计规范），没有"做什么"（需求分析）。这个 skill 补的是需求分析这一环，让 agent 在动手之前先想清楚。

## nuwa-skill 分析

### 它是什么

**女娲.skill** — 一个"思维蒸馏"框架。输入一个人名，自动完成调研→提炼→验证全流程，生成一个可运行的"人物思维 Skill"。

核心理念：**捕捉 HOW they think，不是 WHAT they said。**

### 工作流程

| 阶段 | 做什么 |
|------|--------|
| Phase 0 | 入口分流：明确人名→直接路径；模糊需求→诊断路径 |
| Phase 1 | 深度调研：6个维度（著作、对话、表达、决策、反模式、边界） |
| Phase 2 | 框架提炼：心智模型（3-7个）、决策启发式、表达DNA、反模式、诚实边界 |
| Phase 3 | Skill 构建：按模板生成 SKILL.md，含角色扮演规则、回答工作流 |
| Phase 4 | 质量验证：保真度评分卡（立场一致性/风格辨识度/边缘诚实度/来源透明度/结构完整度） |

### 提取的 5 个核心维度

1. **心智模型** — 他用什么镜片看世界？（需通过三重验证：跨域复现、有生成力、有排他性）
2. **决策启发式** — 他用什么直觉规则做判断？
3. **表达 DNA** — 句式指纹、风格标签、禁忌词和口癖
4. **反模式** — 他绝对不会做什么？
5. **诚实边界** — 这个 Skill 做不到什么？

### 已有的示例 Skill

Steve Jobs、Elon Musk、Feynman、Munger、Naval、Taleb、张一鸣、张雪峰、MrBeast、Andrej Karpathy 等 14 个。

在中国大陆，GitHub、NPM、PyPI、Docker 等开发资源经常访问不了或极慢。每次 agent 需要 clone 仓库、下载包、拉取镜像时，都要手动配代理。这个 skill 让 agent 知道该用什么代理、怎么配。

**核心内容：**

| 场景 | 配置方式 |
|------|---------|
| Git clone/push | `git config --global url."https://ghfast.top/https://github.com/".insteadOf "https://github.com/"` |
| 环境变量 | `export HTTP_PROXY=http://127.0.0.1:7897`（赵的 Clash Verge 端口） |
| NPM | `npm config set proxy http://127.0.0.1:7897` |
| PyPI | `pip install xxx -i https://pypi.tuna.tsinghua.edu.cn/simple`（清华镜像） |

**为什么是自建的：**
市面上的代理 skill 要么是全局 VPN 方案，要么是针对特定工具的。我这个是把赵的实际环境（Clash Verge 端口 7897、ghfast.top 加速）整理成 agent 可直接参考的文档。不是通用方案，是为赵的环境量身定做的。

当 agent 遇到网络超时、clone 失败、pip/npm 安装失败时，读这个 skill 就知道该用什么代理。

### 2. gufa-frontend — 古法前端需求描述法

**是什么：**
一个需求分析框架。用五个维度（布局、组件、数据、状态、交互）把模糊的前端需求转化为结构化的技术描述。

**解决什么问题：**
用户说"做一个用户管理页面"，agent 不知道该做成什么样——表格还是卡片？要不要搜索？数据从哪来？加载中显示什么？这个 skill 提供了一个标准化的分析框架，让 agent 不用反复追问就能给出合理的技术方案。

**五个维度：**

| 维度 | 问什么 | 示例 |
|------|--------|------|
| **布局** | 页面分几个区域？ | 顶部搜索栏 + 中部表格 + 底部分页 |
| **组件** | 每个区域用什么组件？ | SearchInput + DataTable + Pagination + Modal |
| **数据** | 数据从哪来？什么格式？ | GET /api/users?page=1&keyword=xxx |
| **状态** | 加载中/空数据/错误怎么处理？ | loading → data loaded → empty/error |
| **交互** | 用户操作触发什么？ | 搜索防抖、行点击弹详情、批量删除确认 |

**为什么叫"古法"：**
没有什么高深的技术，就是最朴素的需求分析方法——把一个页面拆成五个维度逐个想清楚。叫"古法"是因为这种方法不依赖任何框架或工具，就是基本功。

**使用方式：**
当用户给模糊的前端需求时，agent 用这五个维度分析一遍，输出结构化描述，然后开始实现。比反复追问"你要什么样式"高效得多。

**为什么是自建的：**
市面上的前端 skill 都是"怎么做"（代码生成、设计规范），没有"做什么"（需求分析）。这个 skill 补的是需求分析这一环，让 agent 在动手之前先想清楚。

## nuwa-skill 分析

### 它是什么

**女娲.skill** — 一个"思维蒸馏"框架。输入一个人名，自动完成调研→提炼→验证全流程，生成一个可运行的"人物思维 Skill"。

核心理念：**捕捉 HOW they think，不是 WHAT they said。**

### 工作流程

| 阶段 | 做什么 |
|------|--------|
| Phase 0 | 入口分流：明确人名→直接路径；模糊需求→诊断路径 |
| Phase 1 | 深度调研：6个维度（著作、对话、表达、决策、反模式、边界） |
| Phase 2 | 框架提炼：心智模型（3-7个）、决策启发式、表达DNA、反模式、诚实边界 |
| Phase 3 | Skill 构建：按模板生成 SKILL.md，含角色扮演规则、回答工作流 |
| Phase 4 | 质量验证：保真度评分卡（立场一致性/风格辨识度/边缘诚实度/来源透明度/结构完整度） |

### 提取的 5 个核心维度

1. **心智模型** — 他用什么镜片看世界？（需通过三重验证：跨域复现、有生成力、有排他性）
2. **决策启发式** — 他用什么直觉规则做判断？
3. **表达 DNA** — 句式指纹、风格标签、禁忌词和口癖
4. **反模式** — 他绝对不会做什么？
5. **诚实边界** — 这个 Skill 做不到什么？

### 已有的示例 Skill

Steve Jobs、Elon Musk、Feynman、Munger、Naval、Taleb、张一鸣、张雪峰、MrBeast、Andrej Karpathy 等 14 个。

## 如何应用到 character-card-guide 和 nexus-free

### 应用到 nexus-free（角色卡项目）

**nexus-free 做的是明日方舟角色卡**（蕾缪安、黍等）。nuwa-skill 的方法论可以直接用在角色卡人设的构建上：

| nuwa-skill 维度 | 角色卡对应 | 具体应用 |
|-----------------|-----------|---------|
| 心智模型 | 角色核心性格 | 从剧情原文、语音台词中提取角色的"思维镜片"——她怎么看待世界？ |
| 决策启发式 | 角色行为逻辑 | 在不同场景下她会怎么选择？提取决策规则 |
| 表达 DNA | 台词风格 | 句式、口癖、禁忌词——让 AI 扮演时"像"她 |
| 反模式 | 角色绝对不会做的事 | 比如黍不会做的事，避免 OOC |
| 诚实边界 | 角色不知道的事 | 设定角色的知识边界，避免编造 |

**好处**：现在的角色卡人设是"描述性"的（她长什么样、性格如何），用 nuwa-skill 的方法可以做成"可运行的思维框架"——AI 不只是"知道她"，而是"像她一样思考"。
